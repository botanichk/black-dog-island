## 5. Проверенная команда сборки под X11

Официальная документация и `.github/workflows/build.yml` используют ровно такой вид:

```bash
git clone https://github.com/elkowar/eww
cd eww
git checkout 48f5aa8b379adf29da0b0bb9ca04164f65d8bdaa
cargo build --release --locked --no-default-features --features x11
```

`--locked` безопасен: `Cargo.lock` есть в репозитории. Сборка — из корня репозитория (workspace), с

```bash
CARGO_TARGET_DIR=~/eww-island/build/target
```

Ожидания: 10–25 минут на i7-3537U, пик RAM ~2–3 ГБ, ~3 ГБ в `build/`.
Бинарник: `build/target/release/eww`.

CLI проверен по `crates/eww/src/opts.rs` (master). Работают: `eww daemon`,
`open`, `close`, `close-all`, `open-many`, `reload`, `kill`, `ping`, `list-windows`,
`active-windows`, `state`, `get`, `update`, `poll`, `logs`, `debug`, `graph`, `inspector`.
Не существуют в этой версии: `eww windows`, `eww daemon --kill`.

## 6. Найденные проблемы совместимости

1. **Верхний центр уже занят.** Панель XFCE стоит сверху по центру и автоскрывается до полосы 3 px.
   Пилюля при y=0 попадает на эту полосу; при «умном» автоскрытии панель останется скрытой,
   пока остров открыт. Для прототипа допустимо, но остров не должен резервировать место
   и должен оставаться узким (~460 px), чтобы края полосы-триггера оставались доступны.
2. **Геометрия на X11**: бэкенд Eww под X11 учитывает `geometry` (x/y/width/height) и struts,
   но **игнорирует `anchor`** (это понятие Wayland/layer-shell). Центрировать нужно
   абсолютными пикселями: вычислять при запуске из `xrandr` и передавать
   `eww open island --pos XxY`.
3. **Список окон должен быть событийным.** `xprop -spy -root` по `_NET_ACTIVE_WINDOW`,
   `_NET_CLIENT_LIST`, `_NET_CLIENT_LIST_STACKING`, `_NET_CURRENT_DESKTOP` здесь работает
   (проверено) и избавляет от опроса раз в секунду. Имена/геометрию брать через `wmctrl -lG`
   только при изменении списка клиентов.
4. **Операции с окнами на X11**: активация `wmctrl -i -a ID`, закрытие `wmctrl -i -c ID`,
   перенос на стол `wmctrl -i -r ID -t N`, переключение стола `wmctrl -s N` — всё доступно.
   **Сворачивания в `wmctrl` нет** (xfwm4); нужен `xdotool windowminimize`.
5. **Размытия нет.** picom не установлен, композитинг xfwm4 включён. Дизайн — плотные,
   слегка прозрачные фоны и `border-radius`, без backdrop blur.
6. **Ограничения GTK CSS подтверждены**: нет flex/grid/backdrop-filter/keyframes.
   Раскладка — `box`/`centerbox`/`expander`.
7. **Трей**: не включать `systray`; наблюдатель SNI остаётся у XFCE.

## 7. Предлагаемый первый прототип (минимум)

Eww не устанавливается в систему. Всё живёт в `~/eww-island`.

1. Установить `rust` (нужно разрешение), клонировать репозиторий и перейти на закреплённый коммит
   в `build/eww-src`, собрать только X11 с `CARGO_TARGET_DIR` внутри проекта.
2. Проверить `build/target/release/eww --version`, `eww ping`, `list-windows`.
3. Минимальный конфиг: `eww/eww.yuck`, `eww/eww.scss`, одно окно `island`
   (~460x38, верхний центр, `:stacking "fg"`, `:windowtype "dock"`, **без** `:reserve`).
4. Содержимое, раунд 1: часы/дата, громкость (чтение + клик-мьют), индикаторы рабочих столов,
   заголовок активного окна. Без трея, уведомлений и сворачивания.
5. Скрипт запуска `scripts/run-island.sh`: поднимает демон, вычисляет центрирование,
   открывает окно. Остановка: `eww kill`.
6. Адаптеры — обычный shell, по одному на бэкенд, JSON на stdout:
   `adapters/x11/{workspaces,active-window,windows}.sh` на основе `xprop -spy`.
7. Тестировать при нетронутой панели XFCE; после 10 минут простоя снять CPU/RAM.

Откат на любом шаге: `eww kill`, удалить `build/` и `eww/`. Останется только пакет `rust`.
