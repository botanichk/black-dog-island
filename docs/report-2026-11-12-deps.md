## 2. Зачем вообще нужен `xdotool` и почему сейчас без него

В текущем прототипе `xdotool` **не используется**: в `eww.yuck` его нет ни в одной команде
(проверено поиском по проекту). Единственные внешние команды — `date`, `xprop`, `pactl`, `wmctrl`.

Он понадобится только в следующем раунде, когда появится кнопка «свернуть окно»:

- `wmctrl` умеет активировать (`-a`), закрывать (`-c`), переносить на другой стол (`-t`),
  переключать стол (`-s`), но **не умеет сворачивать** окна.
- EWMH-свойство `_NET_WM_STATE_HIDDEN` только читается; выставить его через `wmctrl -b add,hidden`
  под xfwm4 нельзя — WM это игнорирует.
- `xdotool windowminimize` делает это через запрос к WM и работает в xfwm4.

Вывод: сейчас пакет не нужен. Установим вместе с раундом 2, если вы одобрите кнопку «свернуть».

## 3. Проверка зависимостей сборки Eww под X11

Сборка под X11 (`--no-default-features --features x11`) тянет `gdkx11` + `x11rb`.
`gtk-layer-shell` и `socat` не нужны. Что реально требуется линковщику и `pkg-config`:

| Требование | Чем закрыто | Статус |
|---|---|---|
| `rustc` + `cargo` | — | **НЕТ** |
| `gtk+-3.0` (заголовки и `.pc`) | `gtk3 3.24.52` | есть |
| `gdk-3.0`, `gdk-x11-3.0` | `gtk3 3.24.52` | есть |
| `pango`, `pangocairo`, `pangoft2` | `pango 1.58.2` | есть |
| `cairo`, `cairo-gobject`, `cairo-xlib` | `cairo 1.18.6` | есть |
| `gdk-pixbuf-2.0` | `gdk-pixbuf2 2.44.8` | есть |
| `glib-2.0`, `gio-2.0`, `gio-unix-2.0` | `glib2 2.90.1` | есть |
| `dbusmenu-gtk3-0.4` | `libdbusmenu-gtk3 16.04.0` | есть |
| `atk`, `atk-bridge-2.0`, `epoxy`, `fribidi`, `cloudproviders`, `fontconfig`, `zlib` | системные пакеты | есть |
| `x11`, `xext`, `xi`, `xrandr`, `xcursor`, `xcomposite`, `xdamage`, `xinerama`, `xkbcommon` | системные пакеты | есть |
| `wayland-client`, `wayland-cursor`, `wayland-egl` | системные пакеты | есть |
| компилятор C (`gcc 16.2`), `pkg-config 3.0.10`, `make`, `ld 2.47`, `ar` | `base-devel`-часть | есть |

Проверено не «на глаз»: все 32 зависимости из `Requires`/`Requires-private`
у `gdk-x11-3.0`, `gtk+-3.0` и `dbusmenu-gtk3-0.4` успешно резолвятся `pkg-config`,
заголовки (`gtk.h`, `gdkx.h`, `pango.h`, `cairo.h`, `gdk-pixbuf.h`, `glib.h`, `Xlib.h`,
`dbusmenu-gtk.h`) присутствуют на диске.

Важные детали:

- `libdbusmenu-gtk3` **обязателен даже без трея**: крейт `notifier_host` — неопциональная
  зависимость Eww, а он линкуется с `libdbusmenu-gtk3`. Пакет уже установлен, вместе с `.pc`-файлом.
- `x11rb 0.13.1` — чистый Rust, работает поверх сокета X11. `libxcb`-dev и `xcb`-заголовки
  для сборки **не требуются**.
- SCSS-компилятор (`grass`) и парсер Yuck (`lalrpop`) собираются из Rust-крейтов, системных
  зависимостей не добавляют.
- Версия Rust: `1.99.1` заведомо покрывает MSRV всех зависимостей (у `x11rb` — 1.63,
  у gtk-rs 0.18 — 1.70 и т. п.).
- Ресурсы: 83 ГиБ свободно (сборка займёт ~3 ГБ), 11 ГиБ RAM, 11 ГиБ swap — достаточно.

**Итог: единственная отсутствующая зависимость — сам toolchain Rust.**

## 5. План после разрешения (строго по порядку)

1. Установка `rust`, проверка `rustc --version` / `cargo --version`.
2. Сборка в `build/eww-src`:
   ```bash
   CARGO_TARGET_DIR=~/eww-island/build/target \
     cargo build --release --locked --no-default-features --features x11
   ```
   Ожидаемо 10–25 минут. Фиксирую в отчёте итоговую версию и хеш коммита.
3. Проверка CLI собранного бинарника: `--version`, `list-windows` (после старта демона).
4. **Проверка синтаксиса Yuck и SCSS до показа окна.** Отдельной «сухой» команды проверки у Eww нет,
   поэтому демон запускается в foreground (`--no-daemonize`) с таймаутом, а его stderr/`eww logs`
   читаются как диагностика. Ошибки парсера Yuck и компиляции SCSS выводятся там же.
   Исправляю всё найденное и повторяю проверку до чистого старта:
   - риск №1: выражения в атрибутах вида `:class {cur_ws == n ? "ws active" : "ws"}`;
   - риск №2: интерполяция `${EWW_CONFIG_DIR}` в пути к скрипту;
   - риск №3: `:limit-width`, `:truncate` и другие свойства `label` в текущей версии;
   - риск №4: `border-radius`/`font-family` в SCSS — GTK CSS понимает не всё.
5. Только после чистого парсинга — `scripts/run-island.sh` и визуальная проверка.
6. Замер ресурсов после 5–10 минут простоя: `ps -o %cpu,rss` для демона, число процессов-адаптеров.
7. Отдельный тест конфликта с панелью XFCE (панель остаётся включённой, настройки не меняются):
   - поведение полосы-триггера при наведении на остров;
   - проверка, что панель вызывается по краям триггера;
   - варианты решения без правки XFCE: уменьшение ширины острова, сдвиг по `y`,
     смещение к краю/другой якорь. Решение — за вами, ничего не меняю сам.

## 6. Что не проверено и остаётся риском

- Сборка pinned-коммита на CachyOS фактически не выполнялась: проверены только зависимости и CI upstream.
- Синтаксис `eww.yuck`/`eww.scss` не валидировался — бинарника нет. Это шаг 4 плана.
- Ширина 460 px и высота 38 px выбраны по расчёту, не по факту на экране.

## 7. Откат

- До установки: удалить `build/` и `eww/` — система остаётся нетронутой.
- После установки: `sudo pacman -Rns rust` (плюс `libgit2`, если не нужен другим пакетам),
  затем удалить `build/`, `eww/`, `scripts/`, `adapters/`.
- XFCE не затрагивается ни на одном шаге: автозапуск не настраивается, панель не отключается,
  `xfconf` не изменяется.
