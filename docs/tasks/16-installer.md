# 16: Установщик BDI (install.sh): проверить всё, настроить всё, откатить всё
Правила как в AGENTS.md. Брать после завершения текущих шагов (git status чистый, кроме генерируемых файлов).
Шаг 0 без правок: прочитать docs/BDI-FACTS.md, docs/AUDIT-*.md, docs/TASKS.md (раздел "Решения"), показать план
и ЖДАТЬ слова владельца. Дальше по одному шагу, один шаг - один коммит, после каждого остановка и отчёт.
Цель: `git clone ... && ./install.sh` -> работает на CachyOS и Void Linux, на чистом и на уже настроенном XFCE; всё
меняется только с резервной копией; `uninstall` возвращает прежнее.

## Жёсткие правила
- Сеть, Wi-Fi, Bluetooth, радио, маршруты, DNS не трогать. Пакеты ставить только после показа точной команды и ответа "y".
  Без systemd: не использовать systemctl/busctl там, где можно иначе (проверить по BDI-FACTS B6).
- Тесты без кликов и без реальных изменений сеанса: `--dry-run` и заглушки xfconf-query / gsettings / pacman / xbps-install
  в PATH из /tmp (как заглушка nmcli раньше), HOME переопределяется на /tmp/fakehome. Реальный запуск делает владелец
  (на тестовом пользователе или в виртуалке), агент в своей сессии его не делает.
- Не перезаписывать и не удалять пользовательское. Панель XFCE только отключается (её конфиг остаётся).
- Остров 373 0 619x50 и хаб не менять. Свой Eww из build/, системный `eww` и чужие виджеты не трогать:
  в скриптах нигде нет `pkill eww`/`pkill -x eww`/вызова `eww` без пути (остановка по pid-файлу). Показать grep.

## Шаг 1. Состояние вне репозитория
Реализовать утверждённую схему. После переключения схемы, акцента, обоев `git status` остаётся чистым. Остров и хаб
работают как раньше (замеры до/после, цвета в контрольных точках как в задании 08). Старое состояние мигрирует один раз,
без потерь (разовый скрипт, идемпотентный).

## Шаг 2. Общие функции (lib/)
lib/log.sh, lib/distro.sh (/etc/os-release: arch/cachyos -> pacman, void -> xbps; остальное: "не поддерживается, но check работает"),
lib/backup.sh, lib/journal.sh, lib/features.sh. deps/arch.txt и deps/void.txt: команда -> пакет -> обязательна/нет -> для чего.
Void: пакеты только те, в которых мы уверены, остальное "?" (установщик скажет "поставьте вручную"), без угадывания.

## Шаг 3. `./install.sh check` и `./install.sh doctor` (только чтение)
check: сеанс X11 (не Wayland), XFCE и версия, xfwm4 с композитингом, экран (предупреждение, если меньше 1280x720), все команды из
deps (найдено/нет, пакет), Rust и cargo для сборки Eww, шрифты (Meslo Nerd Font), группы (video, rfkill, audio) и что от них
зависит, NetworkManager/nmcli (иначе вкладка Wi-Fi "недоступно"), noctalia (иначе "цвета с обоев" недоступны), состояние
панели XFCE, чужой владелец org.kde.StatusNotifierWatcher, чужие демоны Eww (список, не трогать), уже установленная копия BDI.
Результат: список изменений, которые сделает install, и файл ~/.local/state/bdi/features (что включено).
doctor: те же замеры, что мы делали руками (BDI-FACTS B11), ожидаемые значения вычисляются: окно острова (размер из конфига),
резерв сверху равен высоте острова, владелец StatusNotifierWatcher наш демон, панель XFCE не запущена, остров один, автозапуск
на месте, каталоги состояния доступны на запись, git чист. `doctor --deep` открывает и закрывает хаб (y=50, ширина как у
острова, углы острова вернулись), с предупреждением "не трогайте мышь". Формат: OK/WARN/FAIL + как исправить; код возврата.
Доказать, что check и doctor ничего не меняют: хэши файлов в ~/.config/xfce4, ~/.config/autostart и дамп `xfconf-query -lv`
до и после одинаковы (на заглушках).

## Шаг 4. `./install.sh install`
Порядок: check -> показ плана -> подтверждение -> резервная копия -> действия -> doctor.
1. Резервная копия уровня 1 (до первого изменения): ~/.local/state/bdi/backup-<дата>/ с архивом ~/.config/xfce4, autostart,
   plank, ulauncher, hypr-wallpicker и дампом xfconf (каналы xfce4-panel, xfce4-session, xfwm4, xfce4-desktop).
2. Журнал уровня 2 changes.log: у каждого изменения тип (xfconf|file|symlink|autostart|gsettings|pkg|process), цель, старое
   значение, новое, время. Нет записи - нет изменения.
3. Пакеты (если нужны): только недостающие, показать команду, ответ "y", журнал.
4. Сборка Eww: закреплённый коммит и patches/*.patch через scripts/build-eww.sh, в build/ репозитория; время и размер показать до
   начала; повторный запуск ничего не пересобирает, если бинарник готов.
5. hypr-wallpicker (необязательно): пин коммита и наши патчи, сборка в build/, хук под XFCE; нет raylib -> пункт пропускается.
6. Панель XFCE: отключить тем способом, который найден в BDI-FACTS B2 (проверить на этой машине, как именно отключена), панель
   остановить после подтверждения, не удаляя её настройки. Проверка: после выхода из сеанса и входа панель не появляется
   (проверяет владелец; в `doctor` строка "после входа проверить").
7. Композитинг xfwm4: если выключен, спросить и включить, журнал. Рабочие столы: если число отличается от 4 (точки острова),
   предупредить и ничего не менять.
8. Автозапуск: одна запись ~/.config/autostart/bdi.desktop (Exec с абсолютным путём к scripts/run-island.sh), один раз,
   остров стартует первым, приложения с значками в трее после него (описать в INSTALL.md). Чужие записи про eww не менять,
   только предупредить.
9. Plank и Ulauncher: темы острова ставятся как необязательные, у каждой отдельный вопрос; настройки бэкапятся и журналируются.
10. Всё включаемое зависит от features: недоступная функция показывает заглушку внутри вкладки (вкладок остаётся ровно 7),
    недоступные кнопки острова скрываются, ширина острова не меняется (растяжка).
Режимы: --dry-run (только план), --yes (без вопросов, кроме установки пакетов), --no-build.

## Шаг 5. `./install.sh uninstall` и `update`
uninstall: идёт по changes.log в обратном порядке; возвращает значение только если текущее равно записанному "новому", иначе
пропускает и сообщает (пользователь поменял сам); восстановление из архива только по явной команде `--restore-backup`.
Пакеты, поставленные установщиком, удаляются только по отдельному "y". Своё состояние (~/.config/bdi) оставляет, если не `--purge`.
update: git pull (только fast-forward), пересборка Eww только если изменился пин или patches/, миграции состояния, doctor.
Доказать на заглушках: install затем uninstall даёт те же хэши файлов и тот же дамп xfconf, что до install.
