# 16: Установщик BDI (install.sh) - личный проект, без переусложнения
Правила как в AGENTS.md. Цель: `git clone && ./install.sh install` -> работает на CachyOS
и Void Linux, на чистом и на уже настроенном XFCE. Всё меняется только после резервной
копии, `uninstall` возвращает прежнее по журналу.

Это панель для себя, а не продукт. Делаем ровно столько, сколько нужно, чтобы поставить
и снять одной командой. Всё остальное - не делать.

## Жёсткие правила
- Сеть, Wi-Fi, Bluetooth, радио, маршруты, DNS не трогать. Пакеты ставить только после показа
  точной команды и ответа "y". Без systemd не использовать systemctl/busctl там, где можно иначе.
- Тесты изолированы (правило в AGENTS.md и docs/TESTING.md): `dbus-run-session`, пустые
  `XDG_*`, `HOME=/tmp/fakehome`, `BDI_*` в /tmp. Реальные Plank, xfconf, dconf, gsettings
  не трогаются. Реальный install запускает владелец, агент - нет.
- Не перезаписывать и не удалять пользовательское. Панель XFCE только отключается
  (её конфиг остаётся). Чужие записи автозапуска не менять.
- Остров 373 0 619x50 и хаб не менять. Свой Eww из build/, системный `eww` и чужие
  виджеты не трогать: остановка только по пути к `build/target/release/eww` или pid-файлу.
  Показать `rg 'pkill|killall|\beww\b'` как доказательство.

Ничего не меняет и не пишет (кроме stdout).

## Шаг 4. `./install.sh install`
Порядок: check -> показ плана -> подтверждение -> резервная копия -> действия -> перезапуск острова.
1. Резервная копия: `~/.local/state/bdi/backup-<дата>/` с `~/.config/xfce4`, `autostart`,
   `plank`, `ulauncher`, и дампом `xfconf-query -lv` по каналам `xfce4-panel`, `xfce4-session`,
   `xfwm4`, `xfce4-desktop`.
2. Журнал `~/.local/state/bdi/changes.log`: тип (xfconf|file|autostart|pkg), цель, старое
   значение, новое, время. Нет записи - нет изменения.
3. Пакеты: только недостающие, показать команду, ответ "y", запись в журнал.
4. Сборка Eww: пин + `patches/*.patch` через `scripts/build-eww.sh` в `build/`. Повторный
   запуск не пересобирает, если бинарник новее пина и патчей. Время сборки сказать заранее.
5. Панель XFCE: `xfce4-panel --quit` + `/sessions/Failsafe/Client2_Command = true`.
   Настройки панели не удалять. Проверить после выхода/входа - владелец.
6. Композитинг xfwm4: если выключен, спросить и включить.
7. Автозапуск: одна запись `~/.config/autostart/bdi.desktop` с абсолютным путём к
   `scripts/run-island.sh`. Повторный install не создаёт дубль.
8. Plank и Ulauncher: необязательные темы, каждая со своим вопросом.

Режимы: `--dry-run` (только план, ничего не пишет), `--yes`, `--no-build`.

## Шаг 5. `./install.sh uninstall` и `update`
- `uninstall`: идёт по `changes.log` в обратном порядке; возвращает значение только если
  текущее равно записанному "новому", иначе пропускает и говорит об этом. Удаляет
  `bdi.desktop` и построенный `build/` (спросить). Своё состояние (`~/.config/bdi`)
  оставляет, удаляет только с `--purge`.
- `update`: `git pull --ff-only`, пересборка только если изменился пин или `patches/`.
- Проверка на заглушках: install затем uninstall возвращает прежние файлы настроек.

## Приёмка
- Каждый шаг: `eww reload` без ошибок, остров 373 0 619x50, git status чистый, один коммит.
- `check` ничего не пишет. `install --dry-run` не создаёт ни журнала, ни бэкапа.
- Повторный `install` идемпотентен: ни дубля автозапуска, ни пересборки.
- `install` затем `uninstall` на заглушках возвращает прежние файлы настроек.
- Владельцу проверить: реальный install на тестовом пользователе, выход и вход (панель
  не вернулась, остров поднялся сам), uninstall.
- Отчёт: что подтверждено командами, что нет.

## Убрано из задания (решение владельца, 2026-11-20)
Чтобы не раздувать личный проект, не делаем:
- `./install.sh report` и сбор диагностики.
- `doctor` и `doctor --deep` (проверку после install делает `check` + глаза).
- Доказательства хэшами файлов и дампами xfconf до/после.
- Матрицу возможностей и деградацию функций по `features`.
- `lib/features.sh`, `~/.local/state/bdi/features`.
- Отдельные вопросы про hypr-wallpicker и его сборку.

Вместо этого: `check` (чтение), `install` (пакеты, сборка, панель, автозапуск),
резервная копия, `uninstall` по журналу, одна страница README и полстраницы TESTING.md.
