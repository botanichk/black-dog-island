# Убрать мёртвое: окно-прототип и сироты SVG

Правила как в AGENTS.md. Модель не принимает картинки: проверять цифрами.
Один шаг - один коммит. Внешний вид не меняется вообще: это чистка.

Цель: убрать из конфига то, что нигде не используется, и не дать SVG-сиротам
копиться в `eww/assets/` при смене шаблонов.

## Что проверено (факты, не догадки)

Прогон по коду без `build/`:

1. **`proto-corners`** - окно-прототип вогнутых углов из этапа 2 (коммит в
   `docs/report-2026-11-12-prototype.md`, там же помечено «остаётся как
   образец»). Ни один скрипт его не открывает: `open` в `adapters/` и
   `scripts/` не встречается вообще. Ссылается на
   `assets/panel-corner-left.svg` и `assets/panel-corner-right.svg`, которых
   **не существует** (в `eww/assets/` лежат только `corner-left.svg`,
   `corner-right.svg`, `panel-corner-{bl,br,tl,tr}.svg`). То есть окно даже
   не отрисуется правильно.
2. **`panel-corner-{bl,br,tl,tr}.svg`** (4 файла) - те же углы прототипа,
   нигде не упомянуты. Углы панели сейчас рисует CSS
   (`.panel-body { border-radius: 0 0 $r-surface $r-surface }`), SVG не нужны.
3. **`wx-bg-*.svg`** (10 файлов: sun, partly, partly-night, cloud, rain,
   drizzle, storm, snow, fog, stars) - старые заливные фоны карточки погоды.
   Карточка берёт JPEG (`wx-bg-${w-bg}.jpg`, 16 сцен), SVG не упомянуты нигде.
   В шаблонах `theme/templates/assets/` их нет, но `apply.sh` их и не удаляет:
   файлы остались с этапа 2 и не перегенерируются.
4. **`panel-strip`** - класс в `eww.scss` (`.panel-body, .panel-strip {}`),
   в `eww.yuck` не встречается. Остался от прежней разметки панели.
5. Классы `.proto`, `.proto-body`, `window.proto-corners` - только под
   `proto-corners`.

## Что НЕ трогать (проверено, что живое)

- **`cond-*.svg`** (10) и **`wifi-*.svg`** (5) - подставляются динамически:
  `cond-${icon}.svg` (eww.yuck:351), `wifi-${wf-level}.svg` (:446),
  `wifi-${net.level}.svg` (:473). Классы `.wifi-excellent` и остальные тоже
  живые: имя приходит из данных.
- **`wx-bg-*.jpg`** (16 сцен) - фон карточки погоды, грузятся из yuck:377.
- **`corner-left.svg`, `corner-right.svg`** - вогнутые углы острова
  (`.flare-left`/`.flare-right`, yuck:118/120).
- **`wsdot*.svg`** - точки рабочих столов.

## Что сделать

### 1. Убрать окно-прототип
- `eww/eww.yuck`: удалить `defwindow proto-corners` (строки 182-190) вместе с
  комментарием к нему.
- `eww/eww.scss`: удалить `window.proto-corners`, `.proto`, `.proto-body`
  (блок 1297-1307 с комментарием).

### 2. Убрать класс `panel-strip`
- `eww/eww.scss`: из `.panel-body, .panel-strip { }` оставить только
  `.panel-body`.

### 3. Удалить SVG-сироты
- `eww/assets/wx-bg-*.svg` - 10 файлов.
- `eww/assets/panel-corner-{bl,br,tl,tr}.svg` - 4 файла.
- Файлы удалять через `git rm`, чтобы они ушли из истории рабочего дерева.

### 4. Не дать сиротам вернуться
`theme/apply.sh` рендерит `theme/templates/assets/*.svg` в `eww/assets/`.
Сейчас он только пишет файлы и никогда не удаляет. Добавить после рендера:
- посчитать список имён, которые есть в `eww/assets/`, но нет ни в шаблонах,
  ни в списке «не генерируется схемой» (там 33 файла: 16 JPEG + 7 прочих
  статичных);
- если такие есть - напечатать их и **не удалять** (удаление «на всякий
  случай» опаснее, чем предупреждение). Достаточно строки
  `сироты в eww/assets (не из шаблонов): ...`.

Почему предупреждение, а не удаление: в `eww/assets/` лежат JPEG-сцены и
статичные SVG, которых в шаблонах нет и не должно быть. Автоудаление по
признаку «нет в шаблонах» снесло бы их все.
