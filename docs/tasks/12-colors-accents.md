## Шаг 1. Выбор акцента (отдельный коммит)
Для любой выбранной палитры (встроенной, сообщества, из обоев) в вкладке "Цвета" ряд из трёх круглых
образцов "Акцент": primary, secondary, tertiary палитры. Клик меняет роль primary острова на выбранный
цвет. on_primary, primary_dim и прочие производные считаются существующей логикой контраста
(palette_lib), текст на акценте читаем (контраст не ниже 4.5:1, показать числа). Выбор хранится в файле
theme/accent (вне git) и сохраняется при смене палитры там, где у палитры есть такой акцент. По умолчанию
primary, как сейчас: без выбора внешний вид не меняется.

## Шаг 2. Каталог сообщества (отдельный коммит)
Конвертер формата mPrimary/mSecondary/... в наши схемы (общий код с palette2scheme.py, не дублировать).
Во вкладке отдельный раздел "Сообщество" под встроенными: карточки по три в ряд, имя (urldecode),
образцы surface и акцента, прокрутка внутри вкладки. id с префиксом c-<слаг>. Битый файл пропускается
с сообщением в stderr, остальные остаются. Режим dark/light берётся из theme/mode. Список строится
из каталога, не копируется в репозиторий. Если каталога нет, раздел не показывается, и вкладка не падает.
Необязательно: фильтр по оттенку акцента (все / синие / зелёные / тёплые / серые).

## Результат шага 1 (18.11)
`build_scheme()` теперь переносит все три акцента палитры образцами
(`accent_primary`, `accent_secondary`, `accent_tertiary`) и подгоняет
выбранный по контрасту; он же становится ролью `primary` острова.
`on_primary`, `primary_dim`, `on_primary_dim` считаются прежней логикой
(`ensure_contrast` + `best_ink`), отдельных правок не потребовали.

Что отбрасывается как вариант: дубли (`secondary == tertiary`: GitHub Dark,
Mine) и серые (насыщенность < 0.12: `m3-content`, `m3-rainbow`,
`m3-monochrome` дают `#c6c6c6` или `#ffffff`). Логика -
`palette_lib.accents_for()`, она же фильтрует акценты M3-схем от обоев.

Выбор хранится в `theme/accent` (в `.gitignore`). Нет файла или в нём
мусор - действует `primary`: внешний вид не меняется.

Контраст (Noctalia, тёмная): `primary #fff59b` 17.68:1, `secondary
#a9aefe` 9.57:1, `tertiary #9bfece` 16.43:1 к фону `#070722`; текст на
плашке 18.79 / 10.17 / 17.46. Светлая: `primary #4a53f4` 4.51:1,
`secondary #575ec5` 4.53:1, `tertiary #0e0e43` 14.87:1 к фону `#e6e8fa`.
Все выше 4.5, подгонка сработала только на светлой.

Проверено:
- `p-noctalia` + `accent tertiary`: `primary` в схеме `#9bfece`, на острове
  найдено 1546 px этого цвета, кольцо активного кружка на месте (18 px).
- Выбор переживает смену палитры и режима: `secondary` у `p-noctalia` ->
  `p-rosepine` даёт `primary #9ccfd8` (её `secondary`), `active` secondary.
- Слоты не разъезжаются с ролями: у `Shinonome` (светлая) `primary`
  серый и выпадает, первым слотом идёт `secondary #8c4351`, клик берёт роль
  из данных, а не жёстко «primary».
- «Остров» (`default`): ряд скрыт (`n = 0`), `eww/colors.scss` и SVG
  вернулись к исходным - `git status` чист по сгенерированным файлам.

Два бага, найденных по ходу (исправлены здесь же):
1. `resolve_source()` для `p-*` печатал путь, но не делал `return 0`, и
   функция доходила до `return 1`. Из-за этого `accent` и `mode` молча не
   пересобирали схему у встроенных палитр (`sh -x`: путь печатался, следом
   `return 1`).
2. `accent_active` сначала попал в `colors{}` - валидатор схемы ждёт там
   только `#rrggbb`, сборка падала с «цвет 'accent_active' должен быть
   #rrggbb». Убрано: активная роль видна по самому `primary`.

Ряд в yuck сделан тремя фиксированными слотами, а не `(for ...)`:
вложенный `for` с индексами массивов в этой сборке даёт пустой ряд
(проверено замером - ни одного пикселя цвета акцента на вкладке).

## Результат шага 2 (18.11)
Каталог сообщества подключён. Конвертер не дублировался: у скачанных
палитр формат тот же (`{dark,light}` с `mPrimary/mSecondary/...`), поэтому
их читает `palette_lib.read_palette()`, а общий вход -
`palette_lib.read_community()`. Она отдаёт `(id, палитра, файл)`.

Что важно в реализации:
- id `c-<слаг>` считается от имени БЕЗ `%20`: имена файлов закодированы
  (`Catppuccin%20Mocha%20Green.json`), без `unquote` вышло бы
  `catppuccin-20mocha-20green`. Совпадение слагов разводится хвостом.
- подпись тоже раскодируется, в карточке «Catppuccin Mocha Green», а не
  «Catppuccin%20Mocha%20Green».
- клик применяет по тому же id: `colors-pick.sh` ищет файл через
  `read_community()`, а не через `slug_unique(stem)` - иначе id в карточке
  и id при применении разъехались бы.
- схема пишется в `theme/schemes/c-<слаг>.json`, файл добавлен в
  `.gitignore` рядом с `p-*` и `u-*`: сгенерированное в git не нужно.

Проверено:
- 41 палитра × 2 режима = 82 схемы собираются без ошибок.
- `theme/colors-list.sh` отдаёт `community` (14 рядов по 3) и
  `community_n = 41`; подписи раскодированы, цвета совпадают с полосками
  на экране (ADW `#242424`/`#ffffff`, Atuel `#0a1126`/`#617cb5`, Aura
  `#15141b`/`#ffca85` - замер по пикселям).
- Каталога нет (подмена `HOME`): ключа `community` в JSON нет, раздел не
  рисуется, вкладка работает, встроенные на месте.
- Битый файл (`Broken.json` с мусором): «пропуск палитры сообщества:
  Broken.json: Expecting value», остальные 40 остаются.
- `palette c-aura` применяется: `primary #ffca85` (tertiary Aura),
  `theme/current` = `c-aura`; смена режима и акцента на палитре сообщества
  работает.
- `palette c-nope` -> «нет палитры: c-nope», код 2.

Попутно исправлено: `build_scheme()` принимал акцент, который фильтр
`accents_for()` считает серым. На ADW light `secondary #2e3436` серый и в
ряду кружков его нет, а схема применяла именно его - подсветка показывала
`primary`, а остров красился в серый. Теперь `build_scheme()` проверяет
акцент тем же фильтром и откатывается на первый доступный.

Фильтр по оттенку (необязательный пункт спеки) не делал: раздел и без него
занимает 14 рядов внутри прокрутки, а фильтр потребовал бы отдельного
состояния в yuck.
