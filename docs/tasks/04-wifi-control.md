# Задание 04: Wi-Fi с управлением (черновик, ждёт утверждения владельца)
Черновик спеки. Код не пишется, пока владелец не утвердит.
Модель не принимает картинки: проверка только текстом. Один шаг - один коммит.

## Зачем
`docs/SPEC-hub.md` и `AGENTS.md` фиксируют пробел: вкладка Wi-Fi показывает только
список и умеет подключаться к сетям с сохранённым профилем. Нет выключателя,
отключения, ввода пароля, обновления списка. Задача закрывает этот пробел.

## Что уже есть (проверено, не выдумано)
- `adapters/x11/wifi.sh`: state, ssid, signal, bars, level, n, list, connect <N>.
- Вкладка `wf-content` в хабе: иконка уровня, SSID, строка состояния, список сетей
  кнопками. Клик по сети зовёт `wifi.sh connect <N>` = `nmcli dev wifi connect SSID`.
- `nmcli 1.58.1`, 3 сохранённых Wi-Fi профиля, `rfkill`: soft/hard blocked = no.
- Активная сеть `MyNetwork`, 10 из 12 видимых сетей защищены паролем.

## Проверенные механизмы (это и есть основа спеки)
1. **Выключить/включить радио:** `nmcli radio wifi off|on`. Работает без пароля.
   РИСК: `off` рвёт активное подключение. Нужно подтверждение в интерфейсе.
2. **Отключиться от сети:** `nmcli connection down <NAME>` или
   `nmcli device disconnect wlan0`. Профиль остаётся, автоподключение не
   сработает до ручного `up`.
3. **Пароль без утечки в `ps`:** `nmcli dev wifi connect SSID password ПАРОЛЬ`
   светит пароль в `ps` - так НЕЛЬЗЯ. Проверено, что `nmcli --ask` читает пароль
   из stdin: `printf '%s\n' "$pass" | nmcli --ask dev wifi connect "$ssid"`.
   Пароль не попадает ни в argv, ни в историю шелла.
   ВАЖНО: при неверном пароле `--ask` спрашивает снова и снова - нужен
   `timeout 15` и одна попытка, иначе процесс висит.
4. **Обновить список:** `nmcli dev wifi rescan` + перечитать список.
5. **Ввод пароля в интерфейсе:** виджет `input :password true` в Eww
   (проверено по исходникам `widget_definitions.rs`: `set_visibility(!password)`).
   `onaccept` - по Enter, `onchange` - по вводу.

## План работ (по шагам, каждый шаг - отдельный коммит)
### Шаг 1. Выключатель и отключение
1. В шапке вкладки Wi-Fi - переключатель радио (`hub_tile`-подобная плитка или
   chip): состояние `nmcli radio wifi`, переключение `on|off`.
2. Пока радио выключено, список сетей не показывается, вместо него подпись
   "Wi-Fi выключен" и кнопка "Включить".
3. У активной сети - кнопка "Отключиться".
4. РИСК выключения при активном подключении: перед `off`, если есть соединение,
   спросить подтверждение (две кнопки "Выключить"/"Отмена"), а не рвать молча.

### Шаг 2. Пароль для новых сетей
1. Клик по защищённой сети без профиля открывает поле ввода пароля прямо в списке
   (не модальное окно: GTK3-модалка в Eww - отдельное окно, это ломает стык).
2. Поле: `input :password true`, `onaccept` отправляет пароль, рядом "Отмена".
3. Скрипт `wifi.sh join <ssid> <pass>`:
   - `printf '%s\n' "$pass" | timeout 15 nmcli --ask dev wifi connect "$ssid"`
   - одна попытка, без цикла; код возврата проверяется;
   - при ошибке - текст в интерфейс: "неверный пароль" / "сеть не найдена".
4. Пароль нигде не логируется, ни в файл, ни в `eww update`.
5. Сеть с сохранённым профилем подключается как сейчас, без ввода пароля.

### Шаг 3. Мелочи
1. Кнопка "Обновить" (rescan) с индикацией, что идёт сканирование.
2. Показ открытых сетей без замка (сейчас `locked` в данных уже есть, в UI
   не используется).

## Запреты для этой задачи
- Не ставить пакеты. Всё нужное есть: `nmcli`, `rfkill`, `timeout` (coreutils).
- Не трогать `wpa_supplicant.conf` и профили NetworkManager руками.
- Не выводить пароль в `ps`, логи, `eww update`, историю шелла.
- Не расширять остров и не менять стык хаба.
- Не отключать чужое активное соединение без подтверждения в интерфейсе.

## Приёмка
1. `eww --config eww reload` без ошибок; остров 373 0 619x50, хаб 373 50 619xH.
2. Каждый путь проверен из терминала с выводом команд:
   - `nmcli radio wifi off` -> `nmcli radio wifi` = disabled -> `on` -> enabled;
   - `wifi.sh join` на тестовой сети с верным и неверным паролем;
   - `nmcli connection down` -> состояние отключено -> `up` возвращает.
3. Пароль не виден: `ps -eo args | grep <пароль>` пусто, в логах Eww пусто.
4. После отключения Wi-Fi активная сеть восстанавливается вручную.
5. Клики и ввод пароля агент не проверит: "владельцу проверить глазами".

## Открытые вопросы к владельцу
1. **Подтверждение при выключении Wi-Fi.** Рвать активное соединение сразу или
   спрашивать? Предлагаю спрашивать: одна лишняя кнопка, зато не оборвётся
   загрузка.
2. **Где вводить пароль.** Поле внутри списка сетей (предлагаю) или отдельное
   модальное окно? Модалка в Eww - новое окно, стык с островом ломается.
3. **Скрытые сети.** Сейчас `nmcli dev wifi list` их не показывает. Нужен ли
   ручной ввод SSID для скрытой сети в этой задаче или позже?
4. **Автоподключение.** После `connection down` сеть не поднимется сама. Оставить
   так (ручное управление) или возвращать автоподключение при включении радио?
