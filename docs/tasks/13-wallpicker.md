# Смена обоев шестиугольниками (hypr-wallpicker) вместо xfdesktop-settings
Правила как в AGENTS.md. Модель не принимает картинки: проверять текстом. Новые пакеты и sudo только с разрешения
владельца: сначала список, потом вопрос. Один шаг - один коммит. Остров 373 0 619x50 и хаб не менять.
Сеть и связь: правило из AGENTS.md в силе.

## Что это
https://github.com/Unixcraft-Studios/hypr-wallpicker - отдельная программа на C + Raylib: сетка шестиугольников
с миниатюрами. Выбранный файл отдаётся пользовательскому скрипту-хуку
~/.config/hypr-wallpicker/apply-wallpaper.sh. Заявлена работа на Wayland и X11, проверялась автором на i3
(на XFCE не проверена). Мы на X11, XFCE (xfwm4, композитинг), обои рисует xfdesktop.

## Шаг 0. Диагностика без правок (показать вывод)
1. Клонировать ВНЕ проекта: `git clone https://github.com/Unixcraft-Studios/hypr-wallpicker ~/src/hypr-wallpicker`
   (в eww-island не коммитить, не копировать).
2. Прочитать README и scripts/apply-wallpaper-x11.example.sh: КАК хук получает путь к картинке
   (аргумент $1, переменная, stdin), какое имя класса и размер окна, как задаются папка обоев и опции,
   как включается вызов matugen (он нам не нужен: цвета считает наш theme/from-wallpaper.sh).
3. Зависимости: `pacman -Ss '^raylib'`, `pacman -Qi raylib`, `make -n`. Нужен ли OpenGL 3.3
   (`glxinfo | grep 'OpenGL version'`, если нет glxinfo, сказать). Список пакетов показать владельцу и ждать
   разрешения на установку. `sudo make install` НЕ делать: бинарник запускается из ~/src/hypr-wallpicker.
4. Сборка (после разрешения): `make`, где лежит бинарник, `--help` или как он запускается, папка обоев
   по умолчанию ~/Pictures/wallpapers. У владельца обои в ~/Изображения (кириллица в пути): проверить,
   что программа находит файлы и миниатюры с такими именами ("Чёрный пёс на острове.png", пробелы).
5. Живой запуск окна показать владельцу: на экране окно открывается или нет, на весь экран или рамкой.
   Агент картинок не видит: проверять `wmctrl -lG`, размер окна, класс (`xprop WM_CLASS`).

## Шаг 1. Хук под XFCE: adapters/wallpicker/apply.sh (лежит в проекте)
В ~/.config/hypr-wallpicker/apply-wallpaper.sh символическая ссылка на него (создаёт скрипт установки
adapters/wallpicker/install.sh, идемпотентный).
1. Поставить обои через xfconf-query, с учётом режима одного стола:
   - если /backdrop/single-workspace-mode = true: писать last-image для /backdrop/screen0/monitor<МОНИТОР>/
     workspace<single-workspace-number>/last-image (сейчас 2);
   - иначе для текущего стола (_NET_CURRENT_DESKTOP).
   Имя монитора и ключи брать из `xfconf-query -c xfce4-desktop -l | grep last-image`, не хардкодить
   (сейчас monitorLVDS-1). Если ключа нет, создать (`-n -t string`).
   Путь с пробелами и кириллицей, кавычки, `$()`, `;` в имени файла: безопасно (параметры только в кавычках).
2. Тот же стиль и правило выбора стола уже реализованы в theme/from-wallpaper.sh: переиспользовать
   одну функцию (не копировать логику).
3. Если сейчас активна схема "с обоев" (theme/current и theme/wallpaper-scheme, как это определяет
   вкладка "Цвета"), пересчитать палитру новыми обоями и перезагрузить остров (`--reload`).
   Если активна обычная палитра (не с обоев), цвета НЕ менять, только обои.
4. Пересчёт цвета (noctalia theme) занимает время: запускать после смены обоев, не блокируя окно выбора.
   Ошибки в ~/.cache/eww-island/wallpicker.log, не в stdout.
5. Проверка без картинок: вручную вызвать хук с тестовым файлом (копия обоев с пробелами и кириллицей
   в имени, например /tmp/тест обои (1).jpg): `xfconf-query ... -p ... last-image` показывает новый путь,
   `theme/from-wallpaper.sh --name` совпадает, затем вернуть прежние обои. Обои владельца в конце те же.

## Шаг 2. Окно и запуск: adapters/wallpicker/run.sh
1. Запуск программы с папкой ~/Изображения (если в ней мало файлов, спросить владельца, какая папка).
2. Окно: если оно не на весь экран, развернуть (`wmctrl -r <класс/заголовок> -b add,fullscreen`, затем
   проверка по `wmctrl -lG`). Esc закрывает. Одна копия: если уже запущено, поднять окно (`wmctrl -a`),
   а не запускать вторую.
3. Наше автоскрытие реагирует на полноэкранное окно: на время выбора остров прячется и после закрытия
   возвращается 373 0 619x50. Проверить замером до/во время/после. Если не возвращается или прыгает,
   сказать прямо и предложить обход (не полный экран, а окно по размеру экрана без fullscreen).
4. Запуск отвязанно: `setsid -f ... >/dev/null 2>&1`.

## Шаг 3. Кнопка обоев на острове
1. Кнопка обоев на острове (сейчас запускает xfdesktop-settings) запускает adapters/wallpicker/run.sh.
   Команда в одном месте. xfdesktop-settings остаётся запасным вариантом: если wallpicker не собран или
   упал, запасной запуск с сообщением в логе. Ширина острова 619 не меняется.
2. Повторное нажатие не плодит копии.

## Результат (18.11.2026, коммиты 0dd28b5, fde13a1, c2be400, fc0e2fb)
Пакеты не понадобились ни один. Сборка прошла с первого раза за 76 с на
GCC 16.2.1: cmake, заголовки X11 (Xlib/Xrandr/Xinerama/Xcursor/XInput2),
libglvnd, mesa, alsa-lib, wayland и libxkbcommon уже стояли. Системный
`raylib 6.2-1` из extra есть, но не нужен: 6.2 лежит подмодулем и линкуется
статически. `sudo make install` не делал - бинарник работает из
`~/src/hypr-wallpicker`.

### Шаг 0. Диагностика
- Клон: `~/src/hypr-wallpicker`, коммит `5d3abc2` (2026-11-05). Подмодуль
  `vendor/raylib` пришлось инициализировать вручную (`git submodule update
  --init --depth 1`, 98 МБ), иначе make нечего собирать.
- Контракт хука по `src/apply.c`: `/bin/sh <хук> <полный путь> <rel_x>
  <rel_y>`; `rel_y` от низа окна; запуск в `fork()`, окно не ждёт; ищется
  `~/.config/hypr-wallpicker/apply-wallpaper.sh`, нужен бит `+x`. Без хука
  встроенный fallback умеет только `awww` (Wayland), а его у нас нет -
  то есть без хука клик не делает ничего.
- Окно: `FLAG_WINDOW_TRANSPARENT | FLAG_WINDOW_UNDECORATED`,
  `InitWindow(1920, 1080, "wallpicker")`, не fullscreen; `WM_CLASS` в коде не
  задаётся, GLFW берёт его из заголовка -> на экране `wallpicker`,
  `wallpicker`. Флаги: `-c/--cols`, `-s/--spacing`, `-a/--angle`, `--help`
  нет. Выбор только мышью, Esc закрывает.
- OpenGL 4.2 (Mesa Intel HD 4000), raylib собран с `GRAPHICS_API_OPENGL_33`.
- Кэш миниатюр: `~/.cache/wallpicker/thumbnails-v2`.

### Шаг 1. Хук
`adapters/wallpicker/apply.sh` + `install.sh` (символическая ссылка,
идемпотентно, есть `--remove`). Правило выбора стола вынесено в
`theme/desktop.sh`: его использует и `from-wallpaper.sh`, и хук - одной
копией, а не двумя.

Таблица проверки хука (light-режим владельца, `accent=tertiary`):

| тестовый файл | ключ xfconf | результат |
|---|---|---|
| `/tmp/тест обои (1).jpg` | `/backdrop/screen0/monitorLVDS-1/workspace2/last-image` | записался, `--name` = «тест обои (1).jpg» |
| `/tmp/злой $(touch PWNED) ; rm -rf x.jpg` | тот же | записался дословно, `PWNED` не создан, файл цел |
| `~/Изображения/Чёрный пёс на острове.png` | тот же | вернул обои владельца |

Смена палитры: при `theme/current=wallpaper` хук пересчитал схему
(`colors.scss` -> `$surface: #181c25`, остров замером `181c25`); при
`theme/current=p-noctalia` `colors.scss` не изменился (diff пуст), в лог
ушло «палитра не с обоев - цвета не меняю».

Найдено и исправлено: `$0` в хуке - путь ссылки, поэтому `dirname/../..`
давал `~/.config`, и подключение `theme/desktop.sh` падало («строка 46:
/home/user/theme/desktop.sh: Нет такого файла»). Теперь `readlink -f "$0"`.

### Шаг 2. Окно и запуск
`adapters/wallpicker/run.sh`: `-c 3`, папка `~/Изображения`, `setsid -f`,
повторный запуск поднимает окно. Ширина сетки при умолчании `-c 5` - 1973 px
против экрана 1366, поэтому три колонки (1250 px).

Замеры на тестовой папке из шести одноцветных картинок: центры миниатюр
(231,227), (589,227), (954,226), (231,545), (589,544), (1137,545) - то есть
сетка влезла целиком, окно `1366x768`, `_NET_WM_STATE_FULLSCREEN` стоит.
Остров во время выбора отсутствует (`wmctrl` его не показывает, флаг
`~/.cache/eww-island/autohide-hidden` есть), после закрытия вернулся
`373 0 619x50`.

### Шаг 3. Кнопка
`:onclick` остался один и тот же, изменился `adapters/x11/wallpaper.sh`:
сначала `run.sh`, при неудаче - `xfdesktop-settings`. `:timeout` 3s -> 5s.
Проверено: кнопка открывает окно за 0.18 с; повторное нажатие оставляет
один процесс и одно окно; с `WALLPICKER_BIN=/nonexistent/wallpicker` кнопка
уходит на запасной путь и открывает `xfdesktop-settings` (в логе обе строки).
