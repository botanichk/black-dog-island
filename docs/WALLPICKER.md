# Выбор обоев шестиугольниками (hypr-wallpicker)

Отдельная программа на C + Raylib: сетка шестиугольников с миниатюрами.
Клик по миниатюре ставит обои и передаёт путь нашему хуку. Заменила
`xfdesktop-settings` как основной способ менять обои; родной настройщик
остался запасным вариантом.

- программа: <https://github.com/Unixcraft-Studios/hypr-wallpicker>
- у нас лежит в `~/src/hypr-wallpicker` (вне репозитория острова)
- бинарник запускается оттуда же, в систему **не ставится**, sudo не нужен

## Как это устроено

```
кнопка на острове (eww/eww.yuck, класс "wall")
  -> adapters/x11/wallpaper.sh      основной путь + запасной
  -> adapters/wallpicker/run.sh     одна копия окна, -c 7 -r 85, fullscreen
  -> wallpicker (raylib)            сетка шестиугольников, клик мышью
  -> ~/.config/hypr-wallpicker/apply-wallpaper.sh   (ссылка на наш хук)
  -> adapters/wallpicker/apply.sh   xfconf + пересчёт палитры
  -> theme/desktop.sh               правило выбора стола, одно на всех
```

Контракт хука (из `src/apply.c`, не из README): `/bin/sh <хук> <полный путь>
<rel_x> <rel_y>`, запуск в `fork()`, окно выбора не ждёт. `rel_y` считается от
низа окна.

## Сборка

Нужен только `cmake`, `gcc`, `make` и заголовки X11 — всё уже стоит,
установка пакетов не требуется. raylib 6.2 лежит подмодулем и линкуется
статически, системный `raylib` из репозитория **не нужен**.

```sh
git clone https://github.com/Unixcraft-Studios/hypr-wallpicker ~/src/hypr-wallpicker
cd ~/src/hypr-wallpicker
git submodule update --init --depth 1     # vendor/raylib, 98 МБ
git apply ~/eww-island/patches/hypr-wallpicker-size-and-cancel.patch
make                                       # ~80 с на 4 ядрах
```

### Наши патчи (оба обязательны)

`patches/hypr-wallpicker-size-and-cancel.patch` добавляет в программу две
вещи, которых нет в апстриме:

| что | зачем |
|---|---|
| флаг `-r/--radius <px>` (64…600) | размер шестиугольника задаётся при запуске. В апстриме радиус зашит константой `HEX_RADIUS 200`, и миниатюру меньше 400x400 получить было нельзя |
| клик мимо миниатюр и правая кнопка | закрывают окно, **не меняя обои**. В апстриме окно закрывалось только по Esc, а клик по пустому месту выглядел как «ничего не произошло» |

Патч затрагивает `include/app.h`, `src/app.c`, `src/ui.c`, `src/render.c`,
`src/wallpaper.c` — 55 строк, проверен `git apply --check` на чистом клоне.

`patches/hypr-wallpicker-blur-backdrop.patch` добавляет размытый фон под
миниатюрами:

| что | зачем |
|---|---|
| флаг `-b/--backdrop <файл>` | обои, из которых строится фон. Не указан или файла нет — окно прозрачное, как в апстриме |
| флаг `--blur <N>` | размытие: картинка уменьшается в N раз и растягивается обратно (по умолчанию 16) |
| флаг `--scrim <0…100>` | затемнение фона, процентов (по умолчанию 40) |

Патч затрагивает `include/app.h`, `include/wallpaper.h`, `include/render.h`,
`src/app.c`, `src/wallpaper.c`, `src/render.c` — 357 строк. Ставится **после**
первого патча: он правит те же файлы (`app.h`, `app.c`, `render.c`).

Порядок и проверка на чистом клоне:

```sh
git apply ~/eww-island/patches/hypr-wallpicker-size-and-cancel.patch
git apply ~/eww-island/patches/hypr-wallpicker-blur-backdrop.patch
make                                        # ~80 с на 4 ядрах
```

Оба применены и собраны на клоне `/tmp/test-clone` (GCC 16.2.1): `make`
выходит с кодом 0, бинарник 1.3 МБ.

Бинарник: `~/src/hypr-wallpicker/wallpicker` (1.3 МБ). `sudo make install` не
делаем: иначе в `/usr/local/bin` появится копия, которая не обновляется
вместе с репозиторием.

Проверено на этой машине: GCC 16.2.1, CMake 4.4.5, OpenGL 4.2 (Mesa Intel HD
4000) — raylib собирается с `GRAPHICS_API_OPENGL_33`, 3.3 хватает.

## Установка хука

```sh
adapters/wallpicker/install.sh      # создаёт ссылку, идемпотентно
adapters/wallpicker/install.sh --remove
```

Ставит `~/.config/hypr-wallpicker/apply-wallpaper.sh` ссылкой на
`adapters/wallpicker/apply.sh`. Ссылка, а не копия: правка хука в проекте
действует сразу. Если по этому пути уже лежит чужой файл, скрипт не затирает
его молча, а просит убрать.

## Что делает хук

1. `xfconf-query` пишет `last-image` для действующего стола. Правило стола —
   в `theme/desktop.sh`: при `/backdrop/single-workspace-mode=true` это стол
   `/backdrop/single-workspace-number` (сейчас 2), иначе текущий
   (`_NET_CURRENT_DESKTOP`). Монитор в ключе не хардкодится: префикс берётся
   из существующих ключей, при пустом профиле — из `xrandr`.
2. Если активна схема «с обоев» (`theme/current = wallpaper`), пересчитывает
   палитру новыми обоями через `theme/from-wallpaper.sh` и перезагружает
   остров. **Обычную палитру не трогает**: если выбрана конкретная палитра,
   смена картинки её не отменяет.
3. Всё пишет в `~/.cache/eww-island/wallpicker.log`, не в stdout (stdout
   принадлежит программе выбора).

Путь не разбирается на слова: он всегда в кавычках, поэтому пробелы,
кириллица, `$()`, `;` в имени файла безопасны (проверено).

## Как проверить

```sh
# окно: открывается на весь экран, остров прячется и возвращается
adapters/wallpicker/run.sh
wmctrl -lG | grep -E 'wallpicker|Eww - '
# Esc закрывает; после закрытия остров снова 373 0 619x50

# фон под миниатюрами: обои размыты и затемнены
grep -E 'фон|запуск' ~/.cache/eww-island/wallpicker.log | tail -2
import -window root /tmp/w.png
# резкость верхней полосы (сот нет) должна быть ~0,1, а не ~1,8 как у обоев

# отмена без смены обоев: клик мимо сетки или правая кнопка
# (окно закрывается, last-image не меняется)

# хук без клика, на тестовом файле
cp ~/Изображения/буря.jpeg "/tmp/тест обои (1).jpg"
/bin/sh ~/.config/hypr-wallpicker/apply-wallpaper.sh "/tmp/тест обои (1).jpg" 0.5 0.5
xfconf-query -c xfce4-desktop -p /backdrop/screen0/monitorLVDS-1/workspace2/last-image
theme/from-wallpaper.sh --name
tail ~/.cache/eww-island/wallpicker.log
```

## Размер сетки

Размер, число колонок и зазор задаются переменными `WALLPICKER_RADIUS` (по
умолчанию 85), `WALLPICKER_COLS` (7) и `WALLPICKER_SPACING` (5). При
1366x768 и 32 обоях это все миниатюры сразу, без прокрутки.

Зазор 15 px (апстрим) на 1366x768 читается как отдельные картинки, сетка
расползается; 5 px даёт плотные «соты». Шаг сетки считается как
`1.73205*R + spacing` по X и `1.5*R + spacing` по Y:

| зазор | шаг X | шаг Y | ширина сетки | bbox миниатюр |
|---|---|---|---|---|
| 15 (апстрим) | 162.2 | 142.5 | 1202 px | x=82..1283, y=13..753 |
| **5** | **152.2** | **132.5** | **1137 px** | **x=114..1251, y=33..733** |

| радиус | миниатюра | колонок влезает | видно рядов из 5 |
|---|---|---|---|
| 200 (апстрим) | 400x400 | 5 (сетка 1973 px — шире экрана) | 1.5 |
| 110 | 220x220 | 6 | 4.3 |
| **85** | **170x170** | **7 (1137 px при зазоре 5)** | **все 5** |
| 70 | 140x140 | 7 | все |

Меньше 64 px не имеет смысла: в миниатюре не разобрать картинку.

## Фон под миниатюрами

Окно выбора прозрачное, и 32 яркие миниатюры поверх пёстрых обоев давали
цветовую кашу. Теперь под сеткой лежат **те же обои, что на рабочем столе**,
размытые и затемнённые:

```
run.sh  ->  xfce_current_wallpaper()  (тема/desktop.sh, правило стола одно)
        ->  wallpicker -b <файл обоев> --blur 16 --scrim 40
        ->  LoadBackdrop(): кадр по пропорциям экрана, уменьшить в 16 раз,
            растянуть обратно, снять 40 % яркости
```

Почему так, а не скриншот и не композитор:

- **без picom и без снятия экрана** — на Intel HD 4000 ничего не стоит,
  один проход по картинке при открытии (~0,2 с вместе с разворотом окна);
- **берётся файл обоев**, а не копия экрана: фон совпадает с тем, что
  владелец видит за окном, и не зависит от того, что ещё открыто поверх;
- если обои не найдены, окно остаётся прозрачным, как в апстриме — фон
  не обязателен.

Замеры (обои `кот встречает.png`, скриншот `import -window root`):

| что | значение |
|---|---|
| резкость фона, обои как есть | 1,81 |
| резкость фона на экране | 0,10 (как модель «уменьшить в 16 и растянуть» — 0,04) |
| затемнение при `--scrim 40` | коэффициент 0,600 — ровно 40 % |
| разница с моделью (обои + blur 16 + scrim 40) | 2,3 из 255 |

Силу можно менять переменными при запуске:

```sh
WALLPICKER_SCRIM=60 adapters/wallpicker/run.sh    # темнее
WALLPICKER_BLUR=32  adapters/wallpicker/run.sh    # размытие сильнее
```

**Одна тонкость, на которой легко ошибиться:** затемнение делается в самих
пикселях картинки, а не полупрозрачным прямоугольником поверх. На окне с
`FLAG_WINDOW_TRANSPARENT` полупрозрачный прямоугольник не затемняет, а
делает окно полупрозрачным — рабочий стол просвечивает, и вместо затемнения
получается посветление. Проверено: с прямоугольником просили 40 %, на экране
вышло **посветление на 40 %** (коэффициент 1,401). С правкой пикселей —
0,600, то есть ровно 40 %.

Заодно: `LoadImageColors` отдаёт копию пикселей, правки в ней до текстуры не
доходят — поэтому яркость снимается прямо в `img.data`.

## Как вернуться на xfdesktop-settings

```sh
adapters/wallpicker/install.sh --remove    # убрать хук
```

и в `eww/eww.yuck` вернуть `:onclick` кнопки `wall` на путь
`$HOME/eww-island/adapters/x11/wallpaper.sh` без ветки wallpicker — проще
всего временно переименовать `~/src/hypr-wallpicker/wallpicker`: тогда кнопка
сама уйдёт на запасной путь `xfdesktop-settings` (проверено).

## Ограничения, которые стоит знать

- Форматы: только `.png`, `.jpg`, `.jpeg`, без рекурсии по папкам. Файл с
  расширением `.jpeg`, внутри которого WebP, программа не откроет
  (`WARNING: IMAGE: Failed to load image data` в логе) — у владельца такой
  один: `~/Изображения/железный.jpeg`.
- Сетка при умолчании (`-c 5`) шире экрана: 5 колонок по 361 px = 1973 px
  против 1366. Поэтому `run.sh` зовёт `-c 7 -r 85` (1250 px, все 32 обои
  видны сразу). Больше 7 колонок на 1366x768 не влезает.
- Миниатюры кэшируются в `~/.cache/wallpicker/thumbnails-v2` (31 файл ≈ 10 МБ
  на 32 обои). Первый запуск строит кэш и показывает «Loading».
- Правило выбора и отмены: клик по миниатюре — поставить обои и закрыть;
  клик мимо сетки (нажал и отпустил вне шестиугольников) — закрыть без
  смены обоев; правая кнопка — то же из любого места; Esc — закрыть.
  Протяжка с миниатюры на пустое место не выбирает и не закрывает: чтобы
  отменить, надо нажать именно на пустом месте.
- Программа не умеет `--help`; флаги: `-c/--cols`, `-s/--spacing`,
  `-a/--angle`, `-r/--radius`, `-b/--backdrop`, `--blur`, `--scrim`
  (последние четыре — наши патчи), позиционный аргумент — папка.
- На XFCE апстримом не проверялась (только i3). У нас проверено вживую:
  окно открывается, fullscreen работает, хук вызывается.
